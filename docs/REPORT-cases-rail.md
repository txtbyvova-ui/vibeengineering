# Отчёт: лента кейсов

Переделка блока кейсов на главной. Ветка `feat/cases-rail`, 2026-08-06.
Причина работы: главная не читалась как портфолио одного бюро — каждый кейс имел
свой набор полей и свою длину текста.

Порядок работ: сначала унификация данных, потом вёрстка. Всё, что ниже
помечено числом, измерено на прод-сборке (`vite preview`), а не оценено на глаз.

---

## 1. Унификация контента

Все четыре кейса приведены к одному типу [`CaseStudy`](../src/types/index.ts).
Поля: `id`, `slug`, `client`, `title` (≤60 знаков), `tag`, `year`, `problem`,
`solution`, `result`, `metrics[]`, `stack[]`. Опциональна только ссылка на живой
продукт. Ситуация «у этого кейса есть метрика, у того нет» теперь невозможна по типу.

### Тексты

Приведены к одному тону и близкой длине, разброс внутри ±20%:

| Кейс | problem | solution | result |
|---|---|---|---|
| М.Видео | 117 | 190 | 130 |
| VEgroove | 120 | 186 | 148 |
| Kupikod | 116 | 215 | 118 |
| Альфа-Банк | 112 | 200 | 121 |

Каждый `problem` начинается с задачи клиента, а не с «мы». Повествование
одинаковое во всех четырёх: задача → что сделали → что получилось.

### Метрики

По три у каждого кейса, все фактические — ни одна не выдумана. Там, где не было
маркетинговых цифр, взяты инженерные: срок (`120 ч под ключ`), вес (`400 кг стали
и света`), количество шагов (`1 клик до заявки`).

### Чего не хватило под схему

Пробелы **не заполнены догадками**. Они лежат в `caseDataGaps`
([`src/data/cases.ts`](../src/data/cases.ts)) и видны на самом сайте: `—` вместо
года и пунктирный чип «уточняется» вместо недостающего стека.

| Кейс | Чего не хватает |
|---|---|
| **М.Видео** | стек: чем собран бот и где он крутился. Год `2022` взят из имени файла в архиве (`One Swipe Offer x MVideo-Eldorado 2022.mp4`) — **требует подтверждения** |
| **VEgroove** | стек: фронт, бэкенд, откуда берутся данные. Год запуска. Галерея: в архиве только снимок первого экрана сайта, скриншотов интерфейса нет |
| **Kupikod** | год реализации |
| **Альфа-Банк** | стек: технологий нет в принципе, это концепция — нужно решить, что туда писать. Год реализации |

Стек Kupikod собран целиком из присланных материалов и ничего не додумывает:
`Сталь С245` и `Труба 40×40×4` читаются на чертеже, `Python`, `aiogram`
и `Google Sheets` — на скриншоте кода.

### Отступление от постановки

Категории в постановке: сайт / бот / веб-приложение / AI / инсталляция.
Альфа-Банк не попадает ни в одну — заведена шестая, `Концепция`.
Это осознанное расширение, а не молчаливое; см. раздел «Что выбивается».

## 2. Горизонтальная лента

[`src/components/ui/CaseRail.tsx`](../src/components/ui/CaseRail.tsx),
[`CaseCard.tsx`](../src/components/ui/CaseCard.tsx).

Нативный `overflow-x: auto` + `scroll-snap-type: x mandatory`.
**Перехвата вертикальной прокрутки нет** — ни ручного, ни через pin. Поэтому
тач-свайп, трекпад и shift+wheel работают сами собой, а скролл страницы
на мобильном остаётся скроллом страницы.

| Требование | Как сделано | Замер |
|---|---|---|
| Одинаковые карточки | ширина и `snap-start` на `<li>`, карточка тянется на слот | 416×630 на 1440 px, 319×618 на 375 px — все четыре совпадают |
| Мобила ~85vw | `w-[85vw]` ниже `sm` | 319 px при 375 px вьюпорта = **85.0%** |
| Кнопки ← → на десктопе | скрыты ниже `md` | `display: none` на 375 px; на 1440 px «назад» `disabled` в начале, «вперёд» `disabled` в конце |
| Стрелки клавиатуры | `onKeyDown` на ленте | `ArrowLeft`/`ArrowRight` двигают на шаг = расстоянию между карточками |
| Tab не уезжает за кадр | смещение считаем сами | со `scrollLeft: 352` фокус на первой карточке вернул ленту к `0` |
| Индикатор — полоса | ширина = `clientWidth / scrollWidth`, сдвиг по прогрессу | 1440/1792 на десктопе, 375/1363 на мобиле |
| Визуальный хвост | `px-5 md:px-10` внутри скроллера + `scroll-px` под snap + градиенты по краям | левый градиент `opacity: 0` в начале, правый `opacity: 1` |
| lazy, первые 2 — eager | проп `eager` у `Picture` | `eager, eager, lazy, lazy` |

`scrollIntoView` для фокуса намеренно **не** используется: он заодно прокручивает
документ по вертикали. Смещение ленты считается вручную по `getBoundingClientRect`.

## 3. Раскрытие кейса

[`src/components/ui/CaseModal.tsx`](../src/components/ui/CaseModal.tsx).

Портал в `document.body` — обязателен: секция кейсов анимируется Framer Motion,
а `position: fixed` внутри трансформированного предка позиционируется
относительно предка, а не вьюпорта.

Анимация сдержанная: `scale 0.98 → 1` + `fade`, 240 мс, `cubic-bezier(0.16, 1, 0.3, 1)`.
Фон затемняется и размывается. Никакого parallax, tilt и кастомного курсора.

| Требование | Замер |
|---|---|
| Esc закрывает | диалог удалён из DOM |
| Клик по фону закрывает | удалён, фокус вернулся на карточку 3 |
| Кнопка × | удалён, фокус вернулся на карточку |
| Focus trap | Tab на последнем → первый, Shift+Tab на первом → последний, оба с `defaultPrevented` |
| `role`/`aria` | `role=dialog`, `aria-modal=true`, `aria-labelledby` резолвится в заголовок кейса |
| Навигация ← → внутри | листает кейсы не закрывая; «назад» `disabled` на первом, «вперёд» на последнем |
| `prefers-reduced-motion` | на 50 мс после клика: `opacity: 1`, `transform: none` у диалога и подложки — появление мгновенное |
| Скролл внутри, body заблокирован | `canScrollPage: false`, позиция страницы `2083` восстановлена после закрытия точно |
| Без layout shift | компенсация ширины полосы; на этом сайте полоса скрыта, компенсация нулевая |

### Три вещи, которые пришлось чинить по ходу

1. **`overflow: hidden` на `body` не годится для блокировки скролла.** Overflow
   всплывает на вьюпорт, тот перестаёт быть прокручиваемым, и смещение схлопывается
   в ноль — открыв кейс из середины страницы, после закрытия оказываешься наверху.
   Замерено. Заменено на `position: fixed` + отрицательный `top` + ручной возврат
   с `behavior: "instant"` (глобальный `scroll-behavior: smooth` иначе разыграл бы
   возврат анимацией).
2. **Содержимое модалки не листалось с клавиатуры** — в focus trap попадали только
   кнопки шапки (их всего 2–3). Прокручиваемой области добавлен `tabIndex={0}`,
   WCAG 2.1.1.
3. **Шапка сайта просвечивала сквозь оверлей.** `mix-blend-difference` инвертируется
   относительно подложки и остаётся читаемой поверх неё. Гасится классом
   `body.modal-open`, который ставит сама модалка.

## 4. Ограничения соблюдены

- Hero не тронут.
- Новых библиотек анимаций нет — используется уже стоявший Framer Motion
  (`AnimatePresence`, `motion`).

- SEO/JSON-LD не сломан: блок в `index.html` не редактировался, на странице
  теперь два `ld+json` и оба парсятся — исходный `@graph`
  (`Organization`, `LocalBusiness`, `WebSite`) и новый `ItemList` из 4 кейсов.

## 5. Замеры

### CLS не вырос

Сравнение прод-сборок обеих веток, `PerformanceObserver` по `layout-shift`
без `hadRecentInput`, полная прокрутка страницы:

| Ширина | `main` | `feat/cases-rail` |
|---|---|---|
| 1440 px | 0.0098 | **0.0099** |
| 375 px | 0.0152 | **0.0152** |

Обе величины на порядок ниже порога «good» (0.1). Держится за счёт `width`/`height`
на каждом `<img>` и фиксированных пропорций обложек.

### Вес

| | было | стало |
|---|---|---|
| Медиа за всю прокрутку | 1332 kB | **55.2 kB** |
| Медиа на первом экране | 0 kB | **17.4 kB** |
| Всего на первом экране | 231 kB | 236.8 kB |
| JS | 289.24 kB / 94.99 gzip | 303.58 kB / **99.46 gzip** |
| CSS | 16.98 kB / 4.35 gzip | 21.28 kB / **5.16 gzip** |
| Высота страницы @1440 | 10393 px | 7896 px |

Вес всей страницы упал в 24 раза: галереи и ролик М.Видео (1246 kB) переехали
в модалку и грузятся только по клику.

17.4 kB на первом экране — цена требования «первые две обложки eager»
(`mvideo-billboards-640.avif` 11.9 kB + `vegroove-site-640.avif` 5.4 kB).
Чтобы они не отбирали канал у первого экрана, им проставлен `fetchpriority="low"`.
Бюджет ≤200 kB держится с большим запасом.

### Горизонтальный скролл страницы

`document.documentElement.scrollWidth === window.innerWidth` на обеих ширинах
(375 и 1440). Прокрутка ленты не двигает `window.scrollX`. На мобиле лента
не залипает: snap работает, стрелки скрыты, свайп нативный.

## Что выбивается по смыслу

### Альфа-Банк — рекомендую убрать с главной

Единственный кейс, который не проходит сразу по трём признакам:

- не попадает ни в одну из пяти категорий постановки — под него пришлось заводить
  шестую, `Концепция`;
- у него нет и не может быть стека: это стратегия, а не продукт;
- обложка показывает не работу, а ключевой визуал презентации.

Сайт продаёт сайты, боты и веб-приложения. Этот кейс — про концепцию, которую
приняли и передали делать чужой команде. Держат его только имя клиента и цифра
бюджета. Решение владельца: либо категория `Концепция` остаётся насовсем, либо
кейс уходит с главной и лента становится ровно про то, что бюро продаёт.

### VEgroove — натянут слабее, но заметно

Единственный кейс без галереи: в архиве только снимок первого экрана сайта.
В модалке под текстом пусто, тогда как у Kupikod там четыре изображения.
Лечится присланными скриншотами интерфейса.

### Побочное следствие, о котором стоит знать

`solution` и `result` теперь появляются в DOM только после клика — то есть
краулер их не видит. Компенсировано `ItemList`/`CreativeWork`
([`CasesJsonLd.tsx`](../src/components/ui/CasesJsonLd.tsx)): содержимое отдаётся
машинно-читаемым, без скрытого текста для роботов. Полностью снимется только
пререндером — [BACKLOG §8](BACKLOG.md).
