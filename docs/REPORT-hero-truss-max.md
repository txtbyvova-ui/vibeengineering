# Отчёт — ферма Hero, полная версия спеки (ветка `feat/hero-truss-max`)

Прототип, не прод. Ветка разворачивает [SPEC-hero-truss.md](SPEC-hero-truss.md)
целиком — включая всё, что при мерже MVP было выброшено осознанно, — чтобы
посмотреть на максимальный эффект и урезать после просмотра, а не до.

Замеры: 2026-08-06. Три коммита поверх `main` (`8368892`).

**Короткий вывод.** Эффект работает и стоит дёшево: собственный `draw()` — 0.4–0.6 мс,
около 3 % кадра. Вся заметная цена лежит вне JS, в растре и композите, и главным
виновником оказалась не ферма, а анимация `gridShift` на фоне всей страницы —
28 fps из 38 потерянных. Из самой физики глазом читается прогиб; max-plus почти
не читается, но и стоит почти ничего.

---

## 1. Стенд

Числа без стенда не значат ничего, поэтому:

| | |
|---|---|
| GPU | **Intel HD Graphics 520** (2016, интегрированная) + NVIDIA GTX 950M |
| Chrome | 150.0.7871.187; `2d_canvas`, `gpu_compositing`, `rasterization` — все `enabled` |
| Вьюпорт | 1440×900, `deviceScaleFactor` 2 |
| Сборка | прод (`npm run build` + `vite preview`), не dev-сервер |
| Потолок железа | 60.5 fps (`about:blank`) |

Это **нижняя граница живого десктопа, а не худший случай**: канва и композит
аппаратные, просто fill rate у HD 520 маленький. На современной машине запас
кратно больше; на софтверном растре (`--disable-gpu`, RDP) — хуже, и это
не проверялось.

Инструментовка живёт в самой странице и снимается одним `Runtime.evaluate`
после бенча. Первая версия харнесса гоняла `Input.dispatchMouseEvent` и
`Runtime.evaluate` по CDP в каждом кадре и сама стала узким местом — спалилась
на том, что CPU throttling 4x показывал fps **выше** обычного. Если будете
перемерять — не повторяйте.

## 2. Что развёрнуто поверх MVP

| Что | Было в MVP | Стало |
|---|---|---|
| Передача усилия | radial distance от курсора («фонарик») | **max-plus по графу рёбер**, 3 развёртки, затухание пояс `0.68` / раскос `0.48`, множитель раскоса вверх `0.66` |
| Геометрический отклик | нет (`nudge = 0`) | **прогиб вниз к опорам**: `dy = sagMax·t·anchor`, `dx` — четверть от него к ближней опоре |
| Опоры | нет | `anchor = min(1, dist / (1.5·spacing))` — пролёт выпучивается и умирает на краях |
| Амбиент | одна изгибная форма | две формы (2.4 px/11 с, 1.1 px/17 с) + пульсация alpha силовых поясов ±12 % |
| Полоса канвы | вся секция Hero | **измеряется по боксу h1** — 599 px вместо 900 на 1440×900 |
| Стопы маски | проценты | CSS-переменные из того же замера |
| Watchdog | нет | лестница dpr 2 → 1.5 → 1 → заморозка в `static`, односторонняя |
| Кап dpr | по значению | плюс второй кап по площади буфера (`maxBackingPx`) |
| Прочее | — | дробление path на 1800 сегментов, порог пересборки по ресайзу, сдвиг 0.5 px при dpr = 1 |

Геометрия совпала с прогнозом спеки до числа: **144 узла / 383 ребра** на 1440×900,
канва 1440×599.

## 3. Кадры и частота

| режим | fps страницы | кадр p50 / p95 | `draw()` p50 / p95 |
|---|---|---|---|
| потолок железа (`about:blank`) | 60.5 | 16.7 / 17.2 | — |
| ферма выключена (`static`) | 60.0 | 16.7 / 17.0 | 0 |
| ambient, dpr 2 | 53.4 | 16.7 / 33.4 | 0.4 / 2.1 мс |
| active, dpr 2 → идёт деградация | 33.1 | 20.6 / 50.7 | 0.5 / 1.9 мс |
| active после деградации (dpr 1) | 54.2 | 16.7 / 33.3 | 0.5 / 1.6 мс |
| **active + CPU throttle 4x** | **51.7** | 16.8 / 33.5 | 0.6 / 3.4 мс |
| ambient + CPU throttle 4x | 59.9 | 16.7 / 17.3 | 0.3 / 1.3 мс |

**CPU throttling 4x почти не меняет картину** (51.7 против 54.2) — упор во fill rate,
а не в процессор. Это же объясняет, почему деградация по dpr работает, а урезание
арифметики не дало бы ничего.

На этом GPU watchdog проходит обе ступени лестницы и оседает на dpr 1 при 54 fps.
На машине посильнее он не сработает вовсе.

## 5. Время до интерактива

Четыре **чередующиеся** холодные загрузки live/static, кеш выключен, медианы:

| | DCL | FCP | LCP | TBT |
|---|---|---|---|---|
| ферма живая | 395 мс | 1392 мс | 1392 мс | 1048 мс |
| ферма в `static` | 429 мс | 1352 мс | 1352 мс | 872 мс |

Разброс между прогонами (FCP 1076–2156 мс) перекрывает разницу: **на старте ферма
не стоит ничего измеримого**. Тот ~1 с TBT — это React, Framer Motion и шрифты,
он был и до неё.

Ловушка, в которую я попал сначала: одиночная пара замеров давала TBT 974 против 0
и выглядела как приговор ферме. Это артефакт первой навигации в свежем профиле
(холодный V8 code cache, шейдеры, шрифты). Мерить только чередованием и медианой.

## 6. Где узкие места — A/B

По одному подозреваемому за раз, на одной и той же загруженной странице,
курсор в движении:

| конфигурация | fps |
|---|---|
| маска канвы + анимированный `.bg-grid` | **22.2** |
| снять только маску канвы | 37.5 |
| вернуть маску, остановить `.bg-grid` | **50.7** |
| снять обе | 55.9 |
| канву уменьшить вдвое по высоте | 59.5 |
| канву скрыть (rAF фермы крутится) | 60.1 |

**Главный виновник — не ферма, а `gridShift`.** `.bg-grid` — fixed-слой на весь
экран, `background-position` не композиторное свойство. Сам по себе он почти
бесплатен (без канвы страница держит 60 fps), но в паре с канвой, которая
перерисовывается каждый кадр, стоит **28 fps**. Снят отдельным коммитом —
это правка фона ВСЕЙ страницы, откатывается одним `git revert`.

Порядок рычагов, если резать дальше:

1. **`dprCap` 2 → 1.5** — −44 % заливки при почти неразличимой разнице. На этой
   машине watchdog всё равно уводит dpr вниз через ~2 с после первого движения
   мышью, и переход виден глазом. Поставить 1.5 сразу честнее, чем ловить ступеньку.
2. **`fpsActive` 60 → 30** — вдвое меньше перерисовок. Воспринимаемая задержка
   задаётся `tauPointerMs` (90 мс), а не частотой кадров.
3. **Площадь канвы** — уже урезана с 900 до 599 px по боксу h1.
4. **Маска** стоит ~5 fps, но она же решает, видно ли эффект вообще (см. §8). Не резать.

Резать арифметику **бессмысленно**: три развёртки max-plus — это ~1150 операций
на кадр, единицы микросекунд.

## 7. Жёсткие требования — статус проверки

| # | требование | как проверено |
|---|---|---|
| 1 | `prefers-reduced-motion` → ноль анимации | Режим `static`, rAF остановлен (`drawMs` не меняется между замерами с интервалом 1.5 с). Переключение вживую тоже ловится: `ambient` → `static` за кадр |
| 2 | touch/mobile → статика без интерактива | `matchMedia('(hover:hover) and (pointer:fine)')` = false → `static`; синтетический `pointermove` режим не поднимает. На 375 px: 63 узла, 158 рёбер, один кадр |
| 3 | IntersectionObserver | `threshold: 0` на секции, цикл гаснет вне вьюпорта; плюс явный `visibilitychange` |
| 4 | dpr cap 2 + watchdog | Лестница dpr 2 → 1.5 → 1 → заморозка, односторонняя. Окно — 30 rAF-кадров, деградация после двух плохих окон подряд (~60 кадров). Страница не фризится: цикл просто исчезает |
| 5 | первый экран читаем всегда | `getContext` сломан до загрузки приложения → h1, CTA и метрики на месте, консоль чистая. Вся инициализация под `try/catch`: throw из `useEffect` в React 18 разобрал бы дерево до корня |
| 6 | контент из data-слоя | Без изменений: [hero.ts](../src/data/hero.ts), [heroMetrics.ts](../src/data/heroMetrics.ts); в `.tsx` пользовательских строк нет |

## 8. Два отступления от спеки

Оба по результатам замера, оба отдельными коммитами.

**Watchdog меряет частоту кадров страницы, а не своих отрисовок.** Спека
предлагала окно по 30 отрисовкам. В ambient их 10 в секунду намеренно — окно
растянулось бы на три секунды, а штатный режим засчитался бы как отказ.
Считаем rAF-колбэки; отрисовки идут отдельным счётчиком для телеметрии.

**«Призрак» маски поднят с 0.18 до 0.32, `ghostLeadPx` 120 → 56.** Спека
предполагала заметную пустую зону между микро-лейблом и h1; в фактической вёрстке
там всего ~110 px, и старая маска гасила ровно ту полосу, где ходит курсор —
плюм от нагрузки становился неразличим. Контраст пересчитан по WCAG, а не на глаз:

> худший кадр — две акцентные линии пикового тира внахлёст под акцентным
> курсивом h1. Эффективная alpha `1 − (1 − 0.60·0.32)² = 0.347`, подложка
> `rgb(97, 36, 9)`, контраст `#FF4F00` на ней — **3.61:1**. Заголовок 106 px,
> порог крупного текста 3:1. Проходит. Выше 0.32 поднимать нельзя.

Микро-лейбл защищён по-прежнему клампом тира до T2 выше `y = 220`.

## 9. Ревью: что видно глазом, а что нет

**Видно:**

- **Геометрия Уоррена с иерархией поясов** — это 80 % эффекта. Именно она отличает
  ферму от модного particle-фона, и работает даже в статике на телефоне.
- **Прогиб.** 8 px на панели 104 px: решётка ощутимо проседает под курсором
  и возвращается. Более ценная половина физики.
- **Маска.** Самый недооценённый параметр во всей работе: до правки `ghostAlpha`
  вся физика была технически безупречна и практически невидима. Один коэффициент
  решал, есть эффект или нет.

**Не видно:**

- **Вторая изгибная форма амбиента** (1.1 px, период 17 с) — ноль. Выбрасывается
  без потерь. Работает `majorBreathAmp` — пульсация яркости, а не геометрия.
- **Третья развёртка** max-plus. Она нужна не для вида, а чтобы профиль не зависел
  от fps; стоит копейки, вопрос не стоит.
- **Разница dpr 1 vs 2** на линиях в 1 px — при внимательном взгляде видна,
  при обычном нет.

**Вердикт по max-plus.** Прогиб читается и без него; сам max-plus почти
не читается — но снимать его не стоит, потому что он почти ничего не стоит.

Анизотропию ~4:1 глаз фиксирует, но не осознаёт. Замените max-plus на эллиптическое
radial-затухание с тем же соотношением — 9 из 10 зрителей разницы не назовут.
Где он всё-таки виден: подсветка идёт **по стержням**, а не срезает решётку
поперёк. Эллипс подсвечивает узлы, попавшие в овал; max-plus — те, до которых
усилие дошло по конструкции. У края пролёта, где `anchor` душит прогиб, это заметно.

Экономика: три развёртки — единицы микросекунд на кадр, ~40 строк и три
типизированных массива, из 4.5 kB gzip всей фичи хорошо если 0.6 kB. Резать надо
`fpsActive` и `dprCap` — они дают в сто раз больше.

Если урезать до одного — оставить **геометрию + прогиб + маску**, выбросить вторую
форму амбиента. Если до двух — вернуть max-plus, он дешёвый.

## 10. Что НЕ проверено

Не выдаётся за проверенное:

- реальный телефон (только эмуляция `hover: none` + `pointer: coarse`);
- софтверный растр (`--disable-gpu`), RDP, старые WebView;
- дисплей 120 Гц;
- длительная сессия с HMR и многократным прогоном эффекта;
- контраст пипеткой по скриншоту — считан по формуле WCAG, но не измерен на пикселях;
- Lighthouse TTI как формальная метрика — мерились DCL/FCP/LCP/TBT.

Отдельно: заголовок h1 не появляется на скриншотах под автоматизацией, потому что
`whileInView` у [RevealText](../src/components/ui/RevealText.tsx) в инструментованной
вкладке не отрабатывает. Это свойство стенда, а не регрессия; для съёмки глушится
правилом `h1 * { transform: none !important }` (именно `h1 *` — `RevealText`
рендерит `motion.div`, а не `span`).

## 11. Как перемерять

```bash
npm run build
```

Дальше — превью на 4173 (конфигурация `vite-preview` в `.claude/launch.json`)
и страница с `?debugGrid`: хук выставляет `window.__grid()`, возвращающий
`{ mode, fps, drawFps, drawMs, maxTension, nodes, edges, dpr, canvasH, degradation }`.
`fps` — частота кадров страницы, `drawFps` — частота собственно отрисовок;
в ambient они расходятся намеренно.

Правила замера, выведенные кровью:

- инструментовать страницу изнутри, забирать результат одним eval; CDP-трафик
  в каждом кадре искажает результат до неузнаваемости;
- сравнивать «ферма живая» против «ферма в `static`» через **touch**-эмуляцию,
  а не через `prefers-reduced-motion`: reduce гасит ещё и CSS-анимации страницы,
  и сравнение перестаёт быть честным;
- холодные загрузки чередовать и брать медиану;
- `proc.kill()` не убивает дерево процессов Chrome — следующий запуск с тем же
  `--user-data-dir` цепляется к фоновой вкладке, где rAF придушен.
